## Защита

- Основная публикация закрыта: доступ только владельцу, пока владелец явно не изменит аудиторию.
- Сервер не предоставляет GET/экспорт/удаление ответов. Доступ к базе — только через административные средства платформы.
- POST требует подписанную HttpOnly SameSite=Strict сессию (Secure в production), CSRF-токен, совпадающий Origin, JSON и версию анкеты 2.
- Размер тела ограничен 32 KiB при потоковом чтении, все поля проверяются по схеме, SQL использует параметры.
- D1 ограничивает запросы: 100 выдач сессии и 60 попыток отправки на IP за 10 минут; 8 попыток на сессию. В базе ограничителя — HMAC адреса с меняющимся окном, без исходных IP. Старые записи удаляются при запросах.
- Ответы в survey_submissions. VK отсутствует в аналитическом JSON. private_profiles хранит только AES-256-GCM ciphertext с уникальным IV; связь вычисляется HMAC из кода анкеты. Согласие и его версия записываются отдельно с VK.
- Ключи SURVEY_SIGNING_KEY и VK_ENCRYPTION_KEY — секреты платформы, по 32 случайных байта в Base64. .dev.vars содержит локальные ключи, исключён из Git, chmod 600. Не менять ключ шифрования без плана миграции: потеря ключа делает ссылки невосстановимыми.
- CSP с уникальным nonce, запрет iframe, no-store, nosniff, no-referrer, запрет ненужных возможностей браузера, HSTS на HTTPS.
- Черновик только в sessionStorage, без VK, срок восстановления 4 часа с последнего действия; удаляется после отправки. Восстановление вкладок браузером может сохранять sessionStorage до истечения срока. Скачанный пользователем файл содержит его ответы и требует обычного осторожного хранения.

## Ограничения

Это усиление защиты, не независимый пентест и не гарантия отсутствия уязвимостей. Ограничитель не заменяет сетевую защиту от распределённого DDoS/ботов. У владельца и администратора инфраструктуры остаются полномочия; защищайте их учётные записи MFA. Не публикуйте административные выгрузки. Перед массовым открытым исследованием нужны выбранные владельцем сроки хранения, процесс отзыва согласия/удаления и подходящие организационные меры. Расшифровывать VK можно только в доверенной среде организатора, используя сохранённые ключи. Публичного декриптора нет.

## Работа

npm run dev; npx tsc --noEmit; npm run db:generate; npm run build.
Миграции drizzle/ неизменяемы после применения. Тестовые записи создавались только в локальной базе. Production не содержит тестовых респондентов.


## Деплой на своём сервере (Docker)

```bash
cp .env.example .env && chmod 600 .env
openssl rand -base64 32   # -> SURVEY_SIGNING_KEY (вписать в .env)
openssl rand -base64 32   # -> VK_ENCRYPTION_KEY  (вписать в .env)
docker compose up -d --build
```

Сервис слушает только 127.0.0.1:8080 — наружу отдаётся через reverse-proxy
(nginx/caddy) с TLS. Пример nginx: proxy_pass http://127.0.0.1:8080 +
`proxy_set_header X-Real-IP $remote_addr;` и `TRUSTED_PROXIES=<ip прокси>` в .env.

Бэкап: `tar czf backup.tgz ./data` (SQLite-файл + кэш).

## Где и как хранятся данные

| Что | Где | Как |
|---|---|---|
| Ответы анкеты | volume `./data/survey-db.sqlite`, таблица `survey_submissions` | id (UUID клиента), ответы JSON, HMAC-хеш payload, дата |
| Ссылка VK | таблица `private_profiles` (тот же файл) | AES-256-GCM, ключ `VK_ENCRYPTION_KEY`, AAD = id профиля; отдельно от ответов |
| Сессии/CSRF | cookie клиента (`__Host-survey_session`) | подписывается HMAC (SURVEY_SIGNING_KEY), HttpOnly/SameSite=Strict/Secure |
| Rate-limit | таблица `rate_limits` | HMAC-хеш IP+скоуп, скользящее окно 10 мин, автоочистка |
| Черновик | только sessionStorage браузера | до закрытия вкладки / 4 ч; ссылка VK не сохраняется |
| Секреты | `.env` на сервере (вне Git, права 600) | попадают в контейнер через env_file |

Защита от ботов/накруток: CSP-nonce привязан к apiNonce, CSRF-токен,
минимальный возраст сессии (60 с на сервере + 2 минуты клиентский таймер),
лимит 2 отправки на сессию, лимиты по IP, проверка consent и схемы ответов.
